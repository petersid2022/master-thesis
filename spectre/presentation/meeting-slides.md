## The Three Drafting Strategies

| Strategy | Cost per draft token | When it wins |
|---|---|---|
| **AR baseline** (no draft) | 0 | Always a valid fallback |
| **Model-drafted SD** | 1× draft-model forward pass | Draft is much smaller than target; high acceptance |
| **N-gram drafted SD** | O(N · context) string-match | Repetitive prompts (code, JSON, structured output) |
| **Hybrid (n-gram → model)** | Free on n-gram hit, draft-model otherwise | Best of both |

The hybrid is the contribution. See dispatch at `spectre/src/main.cpp:978-995`,
n-gram lookup at `spectre/src/main.cpp:1286-1323`.

## The Cache-Hierarchy Framing

Speculative decoding *is* speculative execution.

| CPU concept | SD analogue |
|---|---|
| L1 cache hit (1 cycle) | N-gram lookup (microseconds, no model) |
| L2 cache hit (~10 cycles) | Draft model forward pass |
| Main memory (~300 cycles) | Target model forward pass |
| Branch prediction | The drafter |
| Pipeline flush on misprediction | Reject + resample from residual |

Frames the thesis as **inference scheduling**, not just "make SD faster."

## Perplexity — The Formula

For a token sequence under a model `p`:

```
PPL = exp( − (1/T) · Σ_t  log p(x_t | x_<t) )
```

- Average the model's log-probability for each actual next token
- Negate, exponentiate, get one number

In `tokens.csv` I already log `logprob = log p_target` per accepted token:

```python
ppl = math.exp(-mean(logprobs))
```

---

## Perplexity — Intuition

PPL = **effective branching factor**. "If the model picked uniformly from
a shortlist, how long would the shortlist need to be to match its uncertainty?"

| PPL | Meaning |
|---|---|
| 1 | Perfect prediction (probability 1.0 on every token) |
| 2 | As uncertain as a fair coin per token |
| 10 | Roughly 10 equally-plausible options — strong modern LLM on prose |
| vocab size (~32k) | Uniform = untrained model |
| ∞ | Assigned probability 0 to a token that appeared — catastrophic |

Identity: `log₂(PPL) = bits per token`. PPL, cross-entropy, log-loss all
the same quantity in different units.

## PPL for Lossless SD — Sanity Check, Not Quality Metric

**Theorem** (Leviathan 2023, Chen 2023): vanilla SD's accepted-token sequence
is a sample from `p_target` **exactly**, by the acceptance rule
`α(x) = min(1, p(x)/q(x))` + residual resample.

Therefore:

- PPL(SD output) and PPL(target output) have **the same distribution**
- Significant gap → my acceptance code has a **bug** (useful test, I use it)
- No gap → SD is correct, but this doesn't say SD output is "as good" — it
  says they are draws from the same distribution
- Asking "which sample is better" is like asking which coin flip is better

`quality-ppl-trace.png` plots per-token logprob + cumulative PPL with the
AR baseline overlaid. **This is the test I want PPL to pass — and it does.**

## Pareto Frontier — Definition

Two objectives that fight each other (e.g. speed vs quality).

A point is **Pareto-optimal** if no other point is at least as good on
*both* axes. The set of Pareto-optimal points = the **frontier**.

```
quality (lower PPL = better)
  ↑
  │  • F16            ← reference
  │     • Q8_0
  │       • Q5_K_M  ┐
  │          • Q4_K_M ├─ Pareto frontier (legitimate trade-offs)
  │             • Q3_K_M ┘
  │
  │  • Q4_0  ← dominated by Q4_K_M → never pick
  │
  └────────────────────────────→ size or 1/speed
```

Everything *behind* the frontier is strictly worse than something on it.
Choosing between frontier points is a values question, not a measurement one.

## Per-Position Acceptance Probability

Each speculative round: drafter proposes `k` tokens, target verifies, accepts
left-to-right until first rejection (+1 bonus on full accept).

**`p_i` = P(i-th draft token accepted | all earlier ones accepted)**

Empirical estimate per position. Plot in `quality-per-position-empirical.png`.

Good drafter (gentle decay):

```
p_i  1.0 ┤ ▓▓
     0.8 ┤ ▓▓▓▓
     0.6 ┤ ▓▓▓▓▓▓     ← agrees deep into the lookahead
     0.4 ┤ ▓▓▓▓▓▓▓▓
         └─────────────→ i = 1, 2, 3, 4, 5, 6, 7, 8
```

Bad drafter (cliff):

```
p_i  1.0 ┤ ▓
     0.4 ┤ ▓▓          ← useless past position 1
     0.1 ┤ ▓▓▓▓▓▓▓▓
         └─────────────→
```

The cliff says: stop drafting earlier, you're wasting target compute.

## Block Efficiency τ (Leviathan 2023)

Independent-Bernoulli model: assume each position is an independent coin
flip with probability `α`. Then expected accepted tokens per round:

```
τ = E[A] = (1 − α^(k+1)) / (1 − α)
```

(Geometric sum + 1 for the bonus.)

And the wall-clock speedup vs AR baseline:

```
speedup ≈ τ · t_target / ( k · t_draft + t_target )
```

So `quality-per-position-empirical.png` is **literally the plot that
justifies the latency numbers**.

- PPL → "is my SD correct?"
- τ → "*why* is it fast — and what's the optimal `n_max`?"

## Quantization & Memory Bandwidth

Inference on consumer hardware is **bandwidth-bound**, not compute-bound.

- Weights must stream from VRAM/RAM to compute units every forward pass
- Q4_K_M = ~4 bits/weight → ~4× less bandwidth than F16
- Quality loss < run-to-run sampling noise on most tasks

**Q4_K_M is on the Pareto frontier.** Picking F16 over Q4_K_M is paying
3-4× the memory bandwidth for a PPL difference smaller than the noise floor.

This reframes requirement (α) — "model selection" — from "which
architecture?" to "which (architecture, quantization) point on the
Pareto front?"

See `quant-pareto.png` and `quant-bandwidth.png`.

## Backup — The Acceptance Rule

Draft proposes `x ~ q`. Accept with probability:

```
α(x) = min(1, p(x) / q(x))
```

On reject, resample from residual:

```
p̃(x) ∝ max(0, p(x) − q(x))
```

Mass on token `x*` after one step:

- Accepted from draft: `q(x*) · min(1, p(x*)/q(x*)) = min(q(x*), p(x*))`
- Via residual: `(1 − Σ min(p,q)) · p̃(x*) = max(0, p(x*) − q(x*))`
- Sum: `min(p, q) + max(0, p − q) = p(x*)` ∎

**Marginal of accepted token = `p` exactly.** This is the losslessness theorem.

---

## Backup — TV-Distance Bound on Acceptance

Expected per-token acceptance probability:

```
E[α] = Σ_x q(x) · min(1, p(x)/q(x))
     = Σ_x min(p(x), q(x))
     = 1 − ½ Σ_x |p(x) − q(x)|
     = 1 − TV(p, q)
```

So **total variation distance is the theoretical upper bound on speedup**.
The only knob that affects acceptance is how close `q` is to `p`.

Pinsker: `TV ≤ √(½ · KL(p ‖ q))` → high KL ⇒ low acceptance (reverse
doesn't hold tightly).

For n-gram drafter: `q` is a Dirac → acceptance probability per position
= `p_target(x_predicted)` exactly. Justifies the Bernoulli model.

## Backup — PPL Caveat: Tokenizer Dependence

PPL is **tokenizer-dependent**. A 32k-vocab model and a 128k-vocab model
cannot have their PPLs directly compared — the "per-token" average is over
different units (fatter tokens → fewer tokens → different average).

Standard fix: **bits per byte (BPB)** or **bits per character (BPC)**
normalizes out the tokenizer.

Not an issue for this thesis — I always compare the same target model
against itself across decoding strategies. Same tokenizer, fair comparison.
Worth mentioning if asked.
